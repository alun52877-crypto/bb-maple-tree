# Spec:主页列表展示与排序改为只依据"上次浇水时间"

Status: ready-for-agent

## Problem Statement

主页列表卡片右侧目前展示的是"最近养护"(任意养护操作)的时间,列表也按该时间排序。但对用户而言,浇水才是最核心的日常养护操作,而杀菌灌根、杀菌喷药、驱虫喷药、换盆换土都是低频操作。当一株植物刚换过盆却没浇水时,卡片显示的时间很新、排序也靠前,用户无法直观判断哪些植物需要浇水,列表顺序与浇水养护的节奏脱节。

## Solution

主页列表卡片右侧的时间改为"上次浇水时间"(只取自浇水这一养护记录),列表排序改为按上次浇水时间倒序。顶部养护卡片继续反映"最近养护"(不限操作类型),但改为独立选取最近养护最新的植物,与列表排序解耦。同时清理首页模块中不可触达的死代码。

## User Stories

1. As a 植物主人, I want 主页列表卡片右侧显示的时间是上次浇水时间, so that 我能直接掌握每株植物的浇水情况
2. As a 植物主人, I want 列表按上次浇水时间倒序排列, so that 最近浇过水的植物排在前面,符合"最近优先"的浏览习惯
3. As a 植物主人, I want 从未浇过水的植物排在列表最底部, so that 列表顺序稳定可预期
4. As a 植物主人, I want 上次浇水时间相同时按植物名称排序, so that 列表顺序稳定不跳动
5. As a 植物主人, I want 从未浇过水的植物在卡片时间区显示"暂无记录", so that 我知道这株植物还没有浇水记录
6. As a 植物主人, I want 卡片时间文案保持相对时间(今天/昨天/N 天前), so that 界面保持简洁
7. As a 植物主人, I want 顶部养护卡片仍然展示最近养护(不限操作类型)的植物, so that 我不会错过任何养护动态
8. As a 植物主人, I want 养护卡片的选取不受列表排序变化的影响, so that 它始终反映全部植物中最近养护最新的那一株
9. As a 植物主人, I want 记录浇水以外的养护操作(杀菌灌根、杀菌喷药、驱虫喷药、换盆换土)时,主页列表时间与顺序保持不变, so that 低频操作不干扰我对浇水的判断
10. As a 植物主人, I want 给植物浇水后卡片立即显示"今天"且该植物排到列表最前, so that 我获得即时反馈
11. As a 植物主人, I want 植物详情页的摘要展示不受本次变更影响, so that 详情页继续提供完整的养护视角
12. As a 维护者, I want 首页模块中不可触达的死代码被移除, so that 代码库不再误导后续修改

## Implementation Decisions

- 主页列表卡片右侧时间改为绑定已有的"上次浇水时间"装饰字段(来源于植物文档的 `lastWater` 属性),停止使用"最新养护记录"装饰字段
- 上次浇水时间为空时的兜底文案保持"暂无记录"不变
- 列表排序键改为"上次浇水时间"的时间戳,降序;从未浇水的植物(时间戳为 0)自然沉底;同值保留按名称的中文排序
- 顶部养护卡片选取逻辑:新增一个纯函数,从全部植物中独立选取"最近养护"时间戳最大的植物;养护卡片文案模板与消费字段不变;所有植物均无养护记录时保持现有兜底行为(回退到列表第一株植物与默认文案)
- 养护卡片选取与列表排序解耦:二者使用不同的领域口径("最近养护" vs "上次浇水时间")
- 植物详情页摘要("最近养护:XX · 日期")不改
- 死代码清理:删除首页模块中不可触达的快捷浇水记录逻辑及其伴随的请求去重状态,收窄因此不再使用的存储函数导入,删除未被任何模板引用的列表状态装饰字段(含其在写库剥离清单中的对应条目)
- 不改存储结构、不做数据迁移:植物文档的 `lastWater` 属性已存在,且所有写入路径(新增浇水、删除记录、修改记录时间、新建植物)均已正确维护
- 数据库层分页拉取的排序方式(按 `updatedAt` 降序)不变;首页拉取全量数据后在客户端整体排序,分页拉取顺序不影响最终展示

## Testing Decisions

- 测试原则:只测外部可观察行为(排序结果、装饰输出、选取结果),不测实现细节
- 被测模块:植物领域逻辑层的纯函数(排序、装饰、新增的养护卡片选取函数)
- 用例必须覆盖:按浇水时间降序排序;从未浇水的植物沉底;同值按名称排序;养护卡片选取"最近养护"最新的植物(且允许其与列表第一株不同);全部植物无养护记录时的养护卡片选取兜底
- 先例:仓库已有使用 Node 内置 `assert` 与 mock 的存储模块单测(`test/` 目录),新测试沿用同一风格(直接 `require` 纯函数模块,不依赖小程序运行时)
- 页面层不做单测覆盖(依赖小程序运行时);其行为正确性由所调用的纯函数层保证

## Out of Scope

- 植物详情页摘要("最近养护")的变更
- 数据库分页排序字段的同步变更
- 养护卡片文案模板之外的文案调整
- 本 spec 所列之外的死代码清理
- 任何形式的浇水提醒/通知功能
- 新增养护操作类型

## Further Notes

- 本 spec 用词遵循 `CONTEXT.md` 词汇表;注意"上次浇水时间"与"最近养护"是两个不同的领域概念,实现与命名中不得混用
- 变更集中在首页模块与植物领域逻辑层,不触碰任何写入路径
- 变更后卡片时间与详情页"上次浇水"展示同源,语义天然一致
